# UI/UX Review — 2026-08-17

> **Purpose** — A review of the published static site as a reader actually meets it, on a
> phone. Findings and recommendations, ranked.
> **Audience** — You, and whoever picks up the front end next.
> **Method** — Audited the live page at `sports-today-clr.pages.dev`, the compiled
> stylesheet, and today's real slate. Not a mockup review; everything below is what the
> site currently does.
> **Related** — [Design System](DESIGN_SYSTEM.md) · [Experience Principles](../product/EXPERIENCE_PRINCIPLES.md) · [Structure Review](../engineering/STRUCTURE_REVIEW_2026-08-17.md)

---

## Verdict

**The migration preserved the product, not just the pages.** The calm density, the
evidence-first prop rows, the honest empty states and the raw recent line all survived
into a static export that loads in 28 KB. That is the hard part, and it is done.

What is left is mostly **mobile polish and one accessibility defect**. Nothing here is a
redesign; the [Experience Principles](../product/EXPERIENCE_PRINCIPLES.md) rule about
refining before restructuring applies to every item below.

---

## What is working

- **28 KB for a full slate.** 12 game cards, 8 served props, 32 raw-line strips. The
  Streamlit version shipped a 107 MB database to render the same thing.
- **The raw recent line survived the port.** It renders with cleared games marked and a
  tally, which is the feature that lets a reader disagree with the score.
- **Responsive foundations are genuinely good.** 251 `rem` font sizes and **zero** fixed
  `px` sizes; five breakpoints; `:focus-visible` present; 44px touch targets defined.
- **Semantics are mostly right** — `<html lang>`, `<main>`, `<nav>`, and **every one of 40
  images carries an `alt`**.
- **Live scores work on the device.** The browser fetches ESPN directly, which is the only
  approach that works — see the Structure Review §4 for why the server-side version could
  not.

## Findings

### 1. ~~The page has no `<h1>`~~ — **fixed 2026-08-17**

The only heading on the slate page is `<h2>Top Opportunities`. The site name renders in a
`<footer>`. There is no `<h1>` anywhere.

For a screen-reader user this means the page announces no title, and heading navigation
starts mid-document at level 2. For search engines it means the page has no stated subject.

**Fix.** Make the slate's own identity the `<h1>` — the date is the honest choice, since
that is what the page *is*:

```html
<h1 class="page-title">Monday, August 17</h1>
```

Then demote `Top Opportunities` to `<h2>` (already correct) and let section headings follow.
Visual design need not change at all; this is markup, not layout.

### 2. ~~Doubleheaders are indistinguishable~~ — **fixed 2026-08-17**

Today's slate lists **"Cardinals at Reds" twice**, at 10:40 AM and 3:40 PM. The data is
right — two distinct game IDs, a real doubleheader — but a reader scanning the page sees
what looks like a duplicate, and the two "Matchup →" links go to different pages with no
explanation.

**Fix.** When a matchup appears more than once on a slate, label it: `Game 1` / `Game 2`.
`SlateGame` already carries `series_game` and `series_total` for series context; a
doubleheader flag belongs beside them. The card already shows a context chip
(`Series · BAL leads 3-0` renders today), so there is a slot for it with no added height.

### 3. ~~Missing mobile web-app metadata~~ — **fixed 2026-08-17**

You add this to a home screen and read it on a phone. The page is missing everything that
makes that feel native:

| tag | present |
|---|---|
| `viewport` | ✅ |
| `theme-color` | ❌ |
| `apple-touch-icon` | ❌ |
| `apple-mobile-web-app-capable` | ❌ |
| `manifest.json` | ❌ |

Consequences: the phone's status bar stays default-coloured instead of matching the dark
canvas; the home-screen icon falls back to a screenshot; opening from the home screen shows
browser chrome instead of running full-screen.

**Fix.** Four `<meta>` tags and a small `manifest.json`, with `theme-color` set to the app's
canvas colour. Half an hour, and it is the single biggest perceived-quality change
available for a home-screen reader.

### 4. ~~No `prefers-reduced-motion` support~~ — **fixed 2026-08-17**

The stylesheet defines transitions and a pulsing `.live-dot`, but never checks
`prefers-reduced-motion`. Readers who set that preference (vestibular sensitivity, or just
preference) get the animation anyway.

**Fix.** One block at the end of `app.css`:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
  }
}
```

### 5. ~~No skip link~~ — **fixed 2026-08-17**

The nav renders before the slate. A keyboard or switch user tabs through every filter pill
and league toggle before reaching the first game. A standard visually-hidden skip link
fixes this in three lines.

### 6. `aria-label` used only three times — *worth an audit, not alarm*

Icon-only and glyph-bearing controls (`Hide games ▴`, the 🎯 prop-count links, threshold
pills) carry meaning that is partly visual. Three labels across a page with ~30 interactive
elements suggests some are announced as bare text or punctuation.

**Fix.** Audit the controls whose visible text is a glyph or an abbreviation, and give each
an `aria-label` that says what it does. Not a rewrite — a pass.

### 7. The 🎯 prop-count link is doing two jobs — *information design*

`🎯 3 props 90+ →` both *states a fact* (this game has three strong props) and *is a
control* (filter the feed to them). That worked in Streamlit where everything was a rerun.
In a static site with real URLs, the same string being a claim and a button is slightly
ambiguous — especially beside `Matchup →`, which is purely navigation.

**Not a bug, and I would not change it without watching yourself use it.** Flagging it
because it is the one place on the card where two different kinds of thing look alike.

## Recommendations, ranked

| # | change | status |
|---|---|---|
| 1 | Add an `<h1>` | ✅ **done** — visually hidden, names the date; one per page, guarded by a test |
| 2 | Mobile metadata + manifest | ✅ **done** — `theme-color`, touch icon, `standalone` manifest |
| 4 | `prefers-reduced-motion` | ✅ **done** |
| 5 | Skip link | ✅ **done** — with a `:focus-visible` outline on the target |
| 3 | Label doubleheaders | ✅ **done** — `Game 1` / `Game 2`, read from each source's own note |
| 6 | `aria-label` audit | **open** — 1-2 hrs |
| 7 | Reconsider the 🎯 dual role | **open** — observe first; do not change on theory |

**Items 1, 2, 4 and 5 shipped on 2026-08-17** as one commit, with six regression tests in
`web/tests/test_static_export.py` reading the real published output.

Two things went wrong doing them, both worth keeping:

- **Django's `{# #}` is single-line only.** An explanatory comment written as a multi-line
  block rendered its continuation lines as page text — *inside the `<h1>` it was
  explaining*. Use `{% comment %}` for anything longer than one line. A test now asserts
  no comment prose reaches the page.
- **Guessing a colour is not the same as reading it.** The first `theme-color` used an
  invented hex; the canvas is `#090d11`, defined once in `app.css`. Same for the brand
  orange in the generated icons (`#ff7a1a`, not the value I first assumed).

Item 3 shipped the same day. Two notes from doing it:

- **The label is read, not inferred.** MLB StatsAPI gives `doubleHeader: "S"` plus
  `gameNumber`; ESPN states it in a note (`"Doubleheader - Game 2"`). Counting duplicate
  matchups on a slate would also flag a single postponed game listed twice, and would
  number them by whatever order the schedule happened to return. `gameNumber` alone is not
  enough either — StatsAPI sets it on *every* game, so reading it without checking
  `doubleHeader` would stamp "Game 1" across the whole slate.
- **The published site renders from a precomputed cache.** The model was correct
  immediately while the site still showed nothing, because `schedule_cache` held rows
  written before the change. Any change to how a card reads needs the cache cleared and
  `precompute_daily` re-run, or the fix is invisible.

Remaining items are 6 and 7, neither of which a reader would notice today.

## Deliberately not recommended

- **A visual redesign.** The dark warm canvas, single orange accent, and layered surfaces
  are working and are documented in the [Design System](DESIGN_SYSTEM.md). Nothing here
  needs restyling.
- **Adding density controls or a settings page.** The product's premise is that it decides
  what matters so the reader does not have to configure it.
- **A service worker / offline mode.** Tempting for a phone app, but the content is
  date-specific and stale sports data is worse than absent sports data. The honest-data
  rule argues against caching a slate.
